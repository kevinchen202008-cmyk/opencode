🔧 Skill 系统分析

当前代码中未发现独立的 skill 模块。MCP 是主要的扩展机制。

扩展方式

类型 说明 可靠性
MCP (Local) 本地进程 stdio 通信 中
MCP (Remote) HTTP/SSE 连接 中
MCP (OAuth) 需要认证的远程服务 高风险
Plugin (npm) JS/TS 插件 稳定

💡 MCP 可靠性提升建议

短期 (1-2 周)

  1. 进程清理 - 实现 MCP 子进程生命周期管理，退出时强制 kill
  2. 失败隔离 - MCP 失败不应挂起主进程，使用 try-catch 包裹
  3. 超时配置 - 增加 mcp.timeout 配置项，允许用户调整

中期 (1-2 月)

  1. 自动重连 - MCP 断开后自动尝试重连 (3 次)
  2. 健康检查 - 定期检查 MCP 工具可用性
  3. 详细日志 - 增加 MCP 连接、工具调用的详细日志

长期 (季度)

  1. Fallback 机制 - MCP 不可用时使用本地工具替代
  2. 熔断器 - 连续失败后暂停 MCP 调用
  3. 监控告警 - MCP 失败率监控和告警

🎯 你的场景可靠性配置建议

针对: Windows/Linux + GitHub CI/CD + MCP

推荐做法

  1. 避免生产环境使用 MCP - CI/CD 环境中 MCP 稳定性较差
  2. 本地 MCP 添加超时: 
    {
  "mcp": {
    "my-server": {
      "type": "local",
      "command": ["python", "mcp-server.py"],
      "timeout": 30000
    }
  }
}
  3. 监控资源使用 - 定期检查子进程数量
  4. 设置内存限制 - CI job 添加内存限制
  5. 日志级别 - 使用 --log-level DEBUG 排查问题

不推荐

  • ❌ 在 CI 环境中依赖关键业务的 MCP 服务
  • ❌ 使用需要 OAuth 的远程 MCP
  • ❌ 长时间运行的 MCP 会话
